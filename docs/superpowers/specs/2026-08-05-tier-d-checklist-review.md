## 1. 전제 정정 — 생성이 필요한 포스트는 **0개**

캠페인 설계는 티어 D를 "`실무 체크리스트` 부재 = 섹션 **생성** 필요, 슬롭 리스크 등급이
달라 별도 심사"로 분류했다. 8개를 실측한 결과 **그 전제가 틀렸다**:

**8개 전부 이미 체크리스트성 섹션을 보유하고 있다.** 게이트가 실패하는 이유는 콘텐츠
부재가 아니라 **제목 표기**다. `check_digest_structure.py:80`은 리터럴
`clean_body.count("## 실무 체크리스트")`로 세므로, 아래 형태는 모두 `found 0`이 된다.

| 포스트 | 현재 제목 | 위치 | 항목 수 | 하위 구조 |
|---|---|---|---:|---|
| 2026-01-24 | `## 7. DevSecOps 실무 체크리스트` | L378 / 546 (69%) | 평문불릿 15 | — |
| 2026-01-27 | `## 10. 이번 주 DevSecOps 실천 체크리스트` | L222 / 373 (60%) | 평문불릿 9 | — |

| 2026-01-30 | `## 7. DevSecOps 실무 가이드` | L383 / 483 (79%) | 평문불릿 13 | — |

즉 **슬롭 리스크는 사실상 없다** — 새 문장을 쓰는 것이 아니라 제목을 canonical 형태로
수렴시키는 작업이다(티어 C와 같은 클래스, 숫자 대신 **수식어**가 붙은 경우).

콘텐츠 품질 예시 — 2026-03-04는 canonical digest와 동일한 P0/P1/P2 구조에 근거가 붙어 있다:

```markdown
## 조치 체크리스트

### P0 (즉시 조치)

- JWT 키 감사: 모든 JWT 서명키가 소스코드나 설정 파일이 아닌 KMS/HSM에 저장되어 있는지 확인
- 제재 목록 업데이트: AML 모니터링 시스템의 OFAC SDN 및 이란 거래소 주소 목록 갱신
```

## 2. 핵심 제약 — 제목을 바꾸면 무손실 가드에 걸린다

`restore_digest_structure.main()`은 `lossless_tokens(before) != lossless_tokens(after)`면
ABORT한다. **제목 텍스트를 바꾸는 모든 형태**가 이 조건을 건드린다(단어를 지우든 더하든).

따라서 티어 D는 변환기 단독으로 처리할 수 없고, **제목 편집(심사 대상) → 변환기 실행**
2단계가 된다. 2단계의 변환기 실행은 순수 마커 변환이라 ABORT가 걸리지 않는다.

또 하나: R6(`checkbox_global_checklist`)의 앵커는 `^##\s+실무 체크리스트\s*$` — **정확히**
canonical 제목이어야 평문 불릿을 `- [ ]`로 박싱한다. 제목에 수식어를 남기면 R6이 동작하지
않아 `validate_checklists`가 0점을 유지한다.

## 3. 3개 안 실측 비교

세 안 모두 8개 전부 **구조 위반 0**을 달성한다. 차이는 무손실성과 품질 점수다.

| | Option A<br>`## 실무 체크리스트` | Option B<br>`## 실무 체크리스트 (DevSecOps)` | **Option B′ (권장)**<br>canonical + 볼드 리드 |
|---|---|---|---|
| 구조 위반 | 8/8 → 0 | 8/8 → 0 | 8/8 → 0 |
| **삭제되는 단어** | **1~4개/포스트** | 0 | **0** |
| 추가되는 단어 | 0 | 1 (`실무` 등) | 0~2 |
| R6 체크박스 박싱 | 동작 (3~15개) | **미동작** (0개) | 동작 (0~15개) |
| 품질 점수 | +6 ~ +10 | 변화 없음 | +6 ~ +10 |

Option A가 삭제하는 단어(실측): 01-24 `DevSecOps` / 01-27 `이번`·`주`·`DevSecOps`·`실천` /
01-29 `DevSecOps` / 01-30 `DevSecOps`·`가이드` / 02-01 `보안`·`점검` / 03-04 `조치` /
03-07 `실행` / 03-29 `DevSecOps`·`팀`·`액션`·`아이템`. 캠페인 결정 1(무손실)에 위배된다.

### Option B′ 형태

```markdown

**DevSecOps**

...
```

제목은 정확한 canonical → 게이트 통과 + R6 박싱 동작. 수식어는 볼드 리드 라인으로 보존
→ 삭제 0. R2가 per-item `대응 체크리스트`를 볼드로 바꾼 것과 동일한 기법이다.

### 4.1 03-29에 추가 조치가 필요한 이유 (실측 근거)

`### DevSecOps 팀 액션 아이템`만 승격하면 섹션 범위가 다음 `##`까지 열려 있어
**`### 다음 주 주목할 이벤트`의 불릿 3개가 섹션에 포함**되고, R6이 그것을 실무 체크리스트
항목으로 박싱한다. 그 3개는 "KubeCon EU 2026 (3/31~4/3)", "NIST AI RMF 2.0 드래프트" 등
**관찰할 이벤트**이지 실행 항목이 아니다 — 의미가 틀어진다.

따라서 `### 다음 주 주목할 이벤트`를 `##`로 승격해 섹션을 닫는다(마커만 변경, 무손실).
그 결과 체크리스트 섹션에는 bash 코드펜스만 남아 체크박스 0개가 되고 품질 점수도
84로 불변이다 — 03-29의 액션 아이템이 애초에 불릿이 아니라 셸 명령이라는 사실을 그대로 반영한다.

### 4.2 심사가 필요한 판단 2건

1. **02-01 항목의 일반성.** 5개 항목이 "언급된 CVE/취약점에 대한 패치 적용 여부 확인",
   "관련 보안 정책 검토 및 갱신"처럼 포스트 고유 내용이 없는 일반 문구다. 같은 포스트
   L189의 `### 2.2 즉시 조치 사항` 표에는 구체적 조치(FortiOS 즉시 업데이트, SSO 로그 점검,
   관리 인터페이스 IP 화이트리스트)가 있다. **표를 근거로 항목을 구체화하는 것은 유일한
   "생성" 작업**이므로 이 문서 범위에서 제외했다. 제안: 일단 제목만 canonical화하고,
   항목 구체화는 별도 판단.
2. **02-01·03-07의 체크리스트 위치.** 문서 18% / 8% 지점(상단)에 있다. canonical digest는
   하단에 둔다. 게이트는 위치를 검사하지 않고, 섹션 밖 체크박스가 0건이라
   `head` 앵커 축소로 per-item 오탐이 가려지는 위험도 **실측 0건**이다. 이동은
   독자 노출 순서를 바꾸는 편집이라 제안에 포함하지 않았다.

## 5. 적용 절차 (승인 시)

배치당 B2~B8과 동일한 6단계를 따른다. 1단계만 다르다.

1. **제목 편집** — 위 표대로 per-post 편집(스크립트 아님, 8개 수동). 변환기의 ABORT
   가드를 우회하지 않고 **가드 밖에서** 수행한다.
2. `python3 scripts/restore_digest_structure.py <8 files>` — 순수 마커 변환, ABORT 없음
3. `check_digest_structure.py --staged --ratchet` / `check_digest_proper_nouns.py --staged`
4. `python3 scripts/regen_quality_baseline.py` (7건 상승 예상)
5. `pytest scripts/tests/` + `score_cover_honesty.py --all --strict` + `check_posts.py`
6. 멱등 재적용 + `jekyll build` + 펜스 내부 변경 감사(R0 회귀 확인)

## 6. 미해결 (이 문서 범위 밖)

- **게이트의 리터럴 카운트.** `## 실무 체크리스트` 리터럴 substring 카운트라 수식어가
  붙은 정당한 체크리스트를 `found 0`으로 오보고한다. 티어 C(숫자)와 티어 D(수식어)가
  같은 뿌리다. 콘텐츠 수렴으로 해소했으므로(결정 5) 게이트는 그대로 두었으나, 향후
  크론이 변형 제목을 내면 재발한다.
- **`lossless_tokens`의 갭.** 마커 오변환(펜스 내부 `#` → `####`)을 탐지하지 못한다 —
  PR #500 R0의 근본 원인. 괄호 같은 구두점 부착도 토큰 불일치로 오탐한다.
- **`validate_checklists` 스코프.** 문서 전체 `- [ ]` 개수를 세므로 구조 게이트와 의미가
  충돌한다. 캠페인 중 baseline 갱신 24건의 원인.
