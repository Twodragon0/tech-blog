### 1.1 선행 전제 2건이 오진이었다

**오진 A — "98개가 이질적 구조":** `notes/digest-proper-noun-policy.md` §4는 레거시가
이질적이라 정규화기가 clean 처리 못 한다고 기록했다. 그 판단은
`backfill_digest_structure.py --dry-run`이 뱉는 *heading whitelist 경고*에 근거했다.
**결함 프로필로 다시 분류하면 125개 중 99개(79%)가 완전히 동일한 프로필**
(`BOX+H1+NUM+RESP`, 구형 per-item-분석 템플릿)이다.

| 결함 프로필 | 파일 수 | 티어 |
|---|---:|---|
| `BOX+H1+NUM+RESP` | 99 | A |
| `RESP` / `NUM+RESP` / `H1+NUM+RESP` / `BOX` / `BOX+H1+RESP` | 11 | B |
| `MISS`(번호형 체크리스트 보유) | 6 | C |
| `MISS`(체크리스트 부재 — 생성 필요) | 8 | D |
| `MISS`(코드펜스 미닫힘의 부수효과) | 1 | E |

**오진 B — "`broken section numbering` 114건이 독립 결함":** `[1, 1, 2, 3, 1, 2, 3, …]`
같은 파손 시퀀스는 item 바디 안의 LLM 산출 `## N. 기술적 배경` / `## N. 실무 영향`이
최상위 섹션으로 오집계된 **증상**이다. 헤딩 강등만 적용하면 **114 → 7**로 줄어든다.

### 1.2 강등만 적용한 실측 (601 → 21)

기존 `backfill_digest_structure.transform_body`를 코퍼스 전체에 적용해 재측정:

| kind | before | after | 비고 |
|---|---:|---:|---|
| `body H1 heading found` | 261 | **0** | 강등이 전부 해소 |
| `broken section numbering` | 114 | **7** | 대부분 강등의 부수효과 |
| `per-item 대응 체크리스트 heading` | 109 | **0** | ⚠ **블록 삭제**로 달성 |
| `per-item checkbox checklist` | 102 | **0** | ⚠ **블록 삭제**로 달성 |
| `expected exactly one 실무 체크리스트, found 0` | 15 | 14 | |
| **합계** | **601** | **21** | |

즉 결정적 변환으로 해소 가능한 범위는 매우 넓다. 다만 RESP/BOX 211건은 기존 로직이
**독자 노출 콘텐츠를 삭제**해서 달성하므로 그대로 쓸 수 없다(§2 결정 1).

### 1.3 게이트 자체의 취약점

`check_digest_structure.py:80`은 리터럴 `clean_body.count("## 실무 체크리스트")`로
체크리스트를 센다. 따라서 레거시 템플릿의 **번호형** `## 9. 실무 체크리스트`는
인식되지 않고 `found 0`으로 보고된다 — 티어 C 6건이 여기 해당한다.

같은 리터럴이 84행 `head = clean_body.split("## 실무 체크리스트")[0]`의 앵커로도 쓰인다.
번호형 파일에서는 split이 실패해 `head`가 본문 전체가 되므로, 전역 체크리스트의 정당한
`- [ ]`까지 per-item 체크박스로 오탐할 **잠재** 위험이 있다. 코퍼스 실측 결과 현재
이 경로로 부풀려진 BOX 플래그는 **0건**이라 지금은 잠재 위험에 그친다.

### 1.4 코드펜스 미닫힘 1건 (티어 E)

`2026-03-26-…-Kubernetes_Supply_Chain_AI.md`는 코드펜스가 **5개(홀수)**다. 276행이 열고
닫히지 않아 이후 본문 전체가 펜스 안으로 들어간다. 결과:

- 게이트: `_strip_code_fences`가 나머지를 제거하므로 422행의 `## 실무 체크리스트`가 보이지
  않아 `found 0`으로 오보고 (MISS 15건 중 1건이 이 원인)
- **렌더링:** kramdown이 276행 이후 본문을 코드 블록으로 렌더한다 — 독자에게 보이는 실제 결함

펜스를 닫으면 체크리스트가 다시 인식되므로 **MISS가 무손실로 해소**되고 렌더링 버그도
사라진다. 따라서 티어 E는 보류 대상이 아니라 캠페인 대상이다.

코퍼스 전수 검사 결과 펜스 홀수 포스트는 255개 중 **이 1개뿐**이다.

## 2. 확정된 결정

**결정 1 — 무손실 재배치만.** 독자에게 보이는 텍스트는 삭제하지 않는다. 헤딩 강등·
재넘버링은 진행하되, `대응 체크리스트` 본문과 체크박스 항목은 보존한다.

**결정 2 — 제자리 강등(merge 아님).** per-item 콘텐츠를 하단 단일 체크리스트로 옮기지
않는다. `#### 대응 체크리스트` → `**대응 체크리스트**`, `- [ ] x` → `- x`로 변환해
항목과 기사의 인접성을 유지한다. 기존 프로젝트 결정("체크박스만 결함, prose 권장조치
유지", PR #452)과 정합한다.

**결정 3 — 티어 A/B/C/E만 이번 캠페인.** 티어 D 8개는 본문 근거 기반 섹션 **생성**이
필요해 슬롭 리스크 등급이 다르다. 생성본 per-post 사전 심사를 전제로 별도 단계로 분리한다.
(승인 시점에는 티어 E를 D에 포함해 8+1로 봤으나, §1.4 실측으로 E가 무손실 수정임이
확인되어 캠페인에 포함했다. 승인 조건 — "생성이 필요한 것은 별도" — 은 유지된다.)

**결정 4 — 신규 전용 변환기.** `backfill_digest_structure.py`는 수정하지 않는다.
그 파일의 `transform_body`는 PR #452가 싱한 LLM 발행 경로와 의미를 공유하므로, 무손실
분기를 끼워 넣으면 한쪽 수정이 다른 쪽을 깨뜨릴 수 있다.

**결정 5 — 게이트를 약화하지 않는다.** 티어 C는 게이트를 느슨하게 하는 대신 콘텐츠를
canonical 형태(`## 실무 체크리스트`)로 수렴시켜 해소한다.

## 3. 변환기 설계 — `scripts/restore_digest_structure.py`

### 3.1 재사용 경계

`backfill_digest_structure.py`에서 **import 재사용**(수정 없음):
`_split_front_matter`, `_split_preserved_segments`, item-heading 정규식, 최상위 섹션
whitelist 정규식.

새로 구현: 아래 R1~R5와 CLI(`--dry-run` / `--staged` / 파일 인자 / `--limit`).

### 3.2 룰 (순서 의존)

| # | 룰 | 대상 건수 | 무손실 근거 |
|---|---|---:|---|
| R1 | item 영역 내 비-섹션 `#`/`##`/`###` 헤딩 → `####` | 261 | 헤딩 텍스트 보존, 레벨만 변경 |
| R2 | `#{1,4}\s*대응 체크리스트` → `**대응 체크리스트**` | 109 | 헤딩→볼드 강조, 문장 이동 0 |
| R3 | item 바디 `- [ ] x` / `- [x] x` → `- x` | 102 | 체크박스 마커만 제거 |
| R4 | 잔여 최상위 `## N.` 섹션을 1..N 연속 재넘버링 | 7 | 번호만 변경 |
| R5 | `## N. 실무 체크리스트` → `## 실무 체크리스트` | 6 | 번호 제거 |

**순서 제약:**
- **R1 → R2.** R1이 `## 대응 체크리스트`를 `#### 대응 체크리스트`로 강등하므로, R2는
  R1 이후에 실행되어야 강등된 형태까지 잡는다. (R2 정규식이 `#{1,4}`를 받는 이유이기도
  하다 — 두 순서 모두에서 안전하게 동작한다.)
- **R4 → R5.** R5가 번호를 제거하면 그 섹션은 R4의 연속성 계산에서 빠진다. R5를 먼저
  실행하면 R4가 잘못된 시퀀스를 기준으로 재넘버링한다.

**R1 적용 범위:** item 영역(`^### \d+\.\d+` 헤딩이 열고, whitelist의 최상위 섹션 헤딩이
닫는 구간) 내부에만 적용한다. 섹션 intro·경영진 브리핑·위험 스코어카드·분석가 시점·
트렌드·실무 체크리스트·참고 자료와 모든 최상위 `## N.` 섹션 헤딩은 verbatim 유지한다.
`_split_preserved_segments`가 보호하는 prose `#### 권장 조치` 블록도 불변이다.

**R3 적용 범위:** item 영역 내부에만 적용한다. 전역 `## 실무 체크리스트` 하위의
체크박스는 정당한 산출물이므로 건드리지 않는다.

### 3.3 예상 결과

R1~R5 적용 후 잔여 위반은 **티어 D 8건**(`expected exactly one 실무 체크리스트, found 0`)
뿐이다. 즉 `601 → 8`.

### 4.1 배치별 검증 순서

1. `--dry-run`으로 diff 검토 (토큰 감사 포함, §5.1)
2. 적용 → `git add`
3. `check_digest_structure.py --staged --ratchet` → **신규 위반 0**
4. `check_digest_proper_nouns.py --staged` → 0 violations
5. `check_posts.py` → SVG 경고 0
6. `score_cover_honesty.py --all --baseline … --strict` → FAIL 0

10. 멱등성: 변환기 재적용 시 `git diff` 비어 있음

### 4.2 래칫과의 관계

이 캠페인은 래칫이 grandfather한 위반을 실제로 **줄이는** 작업이다. 각 배치에서
`--ratchet`은 "신규 위반 0"만 보장하므로, 위반이 실제로 감소했는지는 별도로 kind별
before/after 카운트를 PR 본문에 명시해 확인한다.

### 4.3 티어 E 개별 판단 (B8)

이 파일은 R1~R5 자동 변환 대상이 아니고 두 가지 판단이 필요하다.

1. **펜스 닫기 위치.** 276행이 여는 펜스의 의도된 내용 범위를 본문에서 읽어 결정한다
   (닫는 펜스 삽입 vs 276행이 잉여 여는 펜스라면 제거). 렌더 결과를 Jekyll 빌드로 확인한다.
2. **`## 3. 대응 체크리스트`의 처리.** 이것은 per-item 헤딩이 아니라 **최상위 번호 섹션**이다.
   R2를 기계적으로 적용해 볼드로 바꾸면 정당한 섹션 헤딩이 사라진다. 펜스 수정 후 이 파일은
   `## 실무 체크리스트`(422행)를 이미 보유하므로 체크리스트 표면이 둘이 되는 문제만 남는다 —
   섹션 리네임 또는 두 섹션 병합 중 무엇이 무손실인지 본문을 보고 결정한다.

이 두 판단 때문에 B8은 자동 변환 배치와 분리하고, PR 본문에 결정 근거를 남긴다.

## 5. 테스트 전략

### 5.1 무손실 불변식 (핵심)

룰별 단위 테스트 외에, **기계적 무손실 검증**을 둔다: 변환 전후 텍스트에서 마크다운
마커(`#`, `-`, `[ ]`, `[x]`, `**`)와 공백을 제거한 뒤 **토큰 다중집합이 동일**해야 한다.
숫자만 바뀌는 R4/R5는 이 검사에서 번호 토큰을 예외 처리한다.

이 검사가 "삭제 금지"를 규칙이 아니라 **테스트로** 강제한다. 5월·6월 proper-noun
파티션에서 오변환 0을 증명한 토큰 감사와 같은 기법이다.

### 5.2 그 외 테스트

- 룰별 positive/negative: 각 룰이 대상만 바꾸고 인접 구조는 건드리지 않음
- 순서 의존 회귀: R2를 R1보다 먼저, R5를 R4보다 먼저 실행하면 결과가 틀림을 명시적으로 검증
- 보호 구간 불변: prose `#### 권장 조치` 블록, 전역 `## 실무 체크리스트` 하위 체크박스,
  코드펜스 내부, front matter
- 멱등성: `transform(transform(x)) == transform(x)`
- 래칫 상호작용: 변환 결과가 신규 위반을 만들지 않음

### 5.3 롤백

배치 단위 `git revert`. 변환기는 in-place이지만 결정적·멱등이므로 revert 후 재적용이
안전하다.
