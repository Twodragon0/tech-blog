# Mac mini 무인 재부팅 복구 시험

상태: 계획만 작성. 실제 재부팅·정전 시험은 수행하지 않았다.

## 성공 기준과 사전 준비

- 현장 담당자, 화면·키보드, 승인된 FileVault 복구 수단을 확보한다. 복구키를 문서·채팅·로그에 붙이지 않는다.
- 유지보수 창에 실행 중인 Paseo 작업을 확인하고 큐 신규 접수를 중단한다. 다른 작업자의 세션을 강제 종료하지 않는다.
- 미커밋 변경, 큐 DB, staging 목록과 원격 검증 기록을 백업한다. 공간과 네트워크를 확인한다.
- 현재 pmset, OS 버전, FileVault 상태, supportsauthrestart, boot time, 각 서비스 상태를 기록한다.
- 별도 장치에서 tailnet 접속과 SSH·Paseo 인증을 사전 확인한다. tailnet은 부팅 전 잠금 해제 경로로 가정하지 않는다.
- 관측 목표는 재시작 후 10분 이내 원격 접속·인증된 앱 응답·큐 복구다. 이는 시험용 판정 기준이며 제품 보장이 아니다.

## 시험 순서

1. 정상 상태에서 작은 테스트 작업을 완료하고 객체 generation과 로컬 잔여량을 기록한다.
2. 현장 복구 가능 여부를 재확인하고, 지원되는 호스트에서 관리자가 대화형 `sudo fdesetup authrestart`를 수행한다. 암호를 인수로 전달하지 않는다.
3. 외부 장치에서 시각을 기록하며 네트워크, SSH, 인증된 Paseo 응답을 순서대로 확인한다. 단순 ping이나 PID만으로 통과시키지 않는다.
4. 로그인 없이 시작해야 하는 서비스와 사용자 로그인 후 시작하는 LaunchAgent를 구분해 상태를 기록한다.
5. 큐 DB 접근, 오래된 lease 회수, staging 보존과 작은 업로드 완료를 확인한다. 원격 검증 전 로컬 삭제가 없었는지 대조한다.
6. 동일 작업의 중복 객체·중복 PR이 생기지 않았는지 확인하고 신규 접수를 재개한다.
7. OS 업데이트 재시작과 전원 복귀는 별도 시험으로 예약한다. 인증 재시작 성공을 콜드 부팅 성공으로 일반화하지 않는다.

## 실패 시 복구

| 증상 | 복구 절차 | 금지할 대응 |
|---|---|---|
| 10분 내 네트워크 미복구 | 외부 경보 후 현장 화면·케이블·전원 확인 | 반복 원격 재부팅 |
| FileVault 잠금 | 현장에서 승인된 계정 또는 복구 수단으로 해제 | FileVault 해제나 키 공개 |
| OS 정상, Tailscale 불가 | 현장에서 네트워크와 데몬 상태 확인, 기존 설정과 비교 | Funnel 활성화·포트 공개 |
| SSH 가능, Paseo 불가 | 실행 계정·launchd·로그·PATH 확인 | 다른 에이전트가 실행 중인데 데몬 재시작 |
| 큐·업로드 실패 | 접수 중지 유지, DB와 staging 보존, lease와 권한 점검 | 실패 파일 일괄 삭제 |
| 디스크 부족 | 검증 완료 잔여 파일·회전 로그만 정리 | 미검증 미디어 삭제 |

10분 목표를 넘기면 시험 실패로 기록하고 현장 복구로 전환한다. 서비스 복구 후 마지막 정상 상태와 현재 상태를 비교하고, 필요한 경우 이번에 변경한 설정만 복원한다. Git reset이나 큐 초기화로 증거를 지우지 않는다.
