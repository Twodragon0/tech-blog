# 자동 번역 운영 연결 준비: Secret, 비용 상한, 복구

상태: T6·T7 구현 전 운영 설계. 이 문서 작성으로 Secret 등록, 모델 선택, 실제 API 호출, 일정 또는 운영 발행 설정을 변경하지 않는다. T5는 Python 호출자가 executor를 명시적으로 주입할 때만 활성화되며, 현재 CLI에는 신규 번역 활성화 옵션이나 기본 네트워크 transport가 없다.

2026-11-08 후속 구현: 로컬 공유 파일시스템의 영속 예약 장부·단일 batch 잠금과 Secret 없는 fixture 검증 workflow를 추가했다. 아래 표는 운영 연결 전 계획의 기준선이며, 구현된 범위와 hosted runner에서의 한계는 [T6 오프라인 검증 기록](2026-11-08-translation-t6-offline.md)을 우선 참고한다. 실제 운영 transport·사용량 정산·token/가격 snapshot·영속 실행 호스트 연결은 여전히 미완료다.

## 현재 코드와 남은 작업

| 경계 | 현재 구현 | 운영 연결 전 필요한 작업 |
|---|---|---|
| 제공자 | T1 명시적 `claude`/`openai`, 키 없으면 실패 | 허용 제공자·모델을 운영 설정에 고정하고 별도 transport 구현 |
| 요청 | T2 구조화된 요청, 출력 최대 1,024 tokens | 입력 token 사전 계산, endpoint allowlist, redirect 금지, 응답 크기 제한 |
| 재시도 | T4 기본 3회·기사당 경과 60초·요청 timeout 30초 | 운영 초기 2회·20초·10초로 축소, 전체 batch deadline 적용 |
| 캐시 | TTL 필수, 최대 24시간, 프로세스 메모리만 사용 | job 재시작 시 적중하지 않음을 비용 산정에 반영; 영속 캐시는 별도 검증 |
| 게시 | T5 입력 상한 1~50 필수, 검증 실패 시 중단 | 환경 Secret·실행 상한·운영 호출자·워크플로 연결 |
| 비용 | 기사 수/재시도/timeout만 제한 | 일일 금액 장부·예약·정산·동시 실행 차단 구현 |
| 관측 | failed manifest와 비공개 검수 자료 | 사용량·예산 잔액·cache hit·배포 SHA 기록 |

T4의 경과 시간은 동기 transport를 강제 취소하는 장치가 아니다. 운영 transport가 실제 connect/read timeout을 지켜야 하고, job 전체 timeout도 별도로 설정해야 한다. T4는 비용 상한을 구현하지 않았다.

## Secret과 비밀 없는 설정

| 항목 | 보관/소비 위치 | 적용 조건 |
|---|---|---|
| `CLAUDE_API_KEY` | 선택한 운영 Actions environment의 Secret → 호출 단계에만 전달 | `provider=claude`인 경우만 필요. 코드가 이 이름을 사용하므로 다른 이름은 명시적으로 매핑 |
| `OPENAI_API_KEY` | 동일 environment의 Secret → 호출 단계에만 전달 | `provider=openai`인 경우만 필요 |
| `GITHUB_TOKEN` | 기존 작업의 최소 권한 토큰 | 검수 PR 생성·artifact/배포 연결용, 번역 키로 사용하지 않음 |
| Slack 자격 증명 | 기존 알림 전용 단계 | 번역 호출 단계로 전달하지 않음 |
| 제공자·모델·규칙 버전·상한 | 비밀 없는 승인된 운영 설정 | `auto`나 모델 기본값 없이 명시 |

두 제공자의 키를 모두 등록할 필요는 없다. 선택된 하나만 호출자에 전달하고 다른 키나 기존 Gemini/DeepSeek 경로로 전환하지 않는다. 기존 workflow에는 legacy `USE_AI`와 여러 Secret 경로가 남아 있다. 신규 T5 연결은 `--use-ai none`을 요구하므로 이 설정을 그대로 재사용해 켤 수 없다. 별도 호출 단계에서 선택 키만 주입해야 한다.

키 검사는 **존재 여부만** 확인한다. 값·길이·부분 문자열·인증 파일·요청 헤더·provider 응답 본문을 로그에 출력하지 않는다. CLI OAuth 로그인은 이 어댑터의 API 키를 대신하지 않는다. `.env`·소스·PR·artifact에 비밀을 넣지 않는다. 회전 시 새 키 검증 후 기존 키를 폐기하고 오래된 실행도 중지한다.

외부 PR 및 신뢰할 수 없는 dispatch 입력에는 운영 Secret과 실호출을 제공하지 않는다. 현재 `repository_dispatch`의 키 비전달 경계를 유지하고, 변경 가능한 원문을 셸 명령이나 설정으로 실행하지 않는다. 이 정책과 환경 접근 제한은 T6에서 테스트해야 한다. 이번 회차에는 원격 Secret 존재 여부나 값에 접근하지 않았다.

## 제안하는 초기 실행 상한

다음 수치는 운영 연결 구현의 시작값 제안이며 **현재 적용된 제한 또는 과금 승인**이 아니다. 모델별 가격은 연결 시점의 공식 가격표에서 확인해 설정 snapshot에 남겨야 한다.

| 상한 | 제안값 | 실패 동작 |
|---|---:|---|
| 첫 검수 canary | 고유 기사 1개, 자동 병합 없음 | 원문/한국어/숫자/CVE/URL을 검수 |
| 일반 batch | 고유 렌더 후보 최대 10개 | 10개 초과는 첫 호출 전 실패; selected만 계산하지 않음 |
| 기사당 시도 | 최대 2회 | 401/403·형식·계약 오류는 즉시 중단 |
| 기사당 경과/요청 timeout | 20초 / 10초 | 남은 시간에 맞춰 timeout 축소 |
| batch 경과/job timeout | 180초 / 5분 | 전체 중지, 부분 게시 금지 |
| 입력/출력 | 요청당 입력 최대 4,096 tokens / 출력 1,024 tokens | 입력 초과를 임의 절단하지 않고 검수로 전환 |
| batch/UTC 일일 금액 | USD 0.25 / USD 1.00 | 사전 예약 불가 시 호출하지 않음 |
| 동시 실호출 batch | 1개 | 여러 runner에서도 같은 장부/lock 사용 |

초기에는 캐시 할인과 적중을 0으로 가정한다. 각 시도 전에 `(입력 token × 입력 단가 + 최대 출력 token × 출력 단가) / 1,000,000`을 상한 비용으로 예약한다. 10기사 × 2회라면 최대 20요청이며, 이 횟수 제한만으로 USD 상한을 보장하지 않는다. token 계산·단가 snapshot이 없으면 실호출하지 않는다.

일일 장부는 프로세스 메모리와 artifact에만 두지 않는다. UTC 날짜·모델·규칙 버전·실행 ID로 영속 기록하고 원자적으로 예약한다. 중복 실행과 job 재시작에서도 예약된 금액을 다시 사용할 수 없어야 한다. 정상 응답의 실제 usage로 정산하되 timeout·불명확한 응답은 보수적으로 예약액을 유지한다. 매일 초기화는 날짜 키 전환으로 처리하며 원장 삭제로 우회하지 않는다. 제공자 콘솔 예산·알림은 보조 통제이며 실제 강제 중단 여부를 확인하기 전에는 hard cap으로 간주하지 않는다.

## 활성화 전 완료 기준

1. fake transport로 키 누락, 선택 외 키 무시, 401/403/429/5xx/timeout, redirect·응답 과대·잘못된 JSON을 검증한다. 실제 API는 테스트에서 차단한다.
2. 가짜 clock/장부로 UTC 날짜 경계, 동시 예약, restart, 재시도 비용, 예산 부족 시 **첫 호출 0회**, timeout의 보수적 정산을 검증한다.
3. T5 security·tech-blog 두 모드에서 실제 임시 글을 생성한다. 원문/번역 불변 계약, 카드 출처 URL, 실제 게시 이력, 통계, 실패 시 기존 글 보존을 확인한다.
4. 집중/전체 pytest, Ruff·format·Mypy, 관련 corpus 게이트와 Jekyll 빌드를 통과한다. Secret 없는 CI와 실패 주입 결과를 PR에 남긴다.
5. 운영 Secret 전달 범위와 담당자를 확정한 뒤 1기사 검수 canary를 수행한다. 실호출 dry-run도 과금될 수 있다. 임시 디렉터리 생성 결과를 검수 PR로 올리고 자동 병합은 켜지 않는다.
6. 검수 병합 후 commit SHA·배포 결과·production canonical URL·backup 경로·RSS 새 항목을 확인한다. 그 뒤 정기 실행 활성화를 별도 변경으로 기록한다.

## 실패 시 중단과 복구

| 실패 신호 | 즉시 조치 | 재개 조건 |
|---|---|---|
| 인증/권한 실패 | 재시도·다른 제공자 전환 금지, 해당 실호출 job 중지 | Secret scope와 키 상태 확인, 누출 의심이면 회전 |
| 429/5xx/timeout | T4 한도 안에서만 재시도; 예산 예약은 유지 | 공급자 회복과 잔액 확인 후 실패 batch만 재검수 |
| 숫자/CVE/URL·한국어·출처 카드 검사 실패 | 부분 게시 금지, failed manifest·안전 검수 자료 확인 | 원문/번역 비교 후 수정된 규칙 버전으로 재검증 |
| 예산/장부/사용량 불명확 | 모든 신규 호출 중지; 잔액을 낙관적으로 복원하지 않음 | 원장·제공자 사용량 대조 및 잔액 확정 |
| 글 생성 후 콘텐츠 검사 실패 | 원격 게시·tracker 갱신 금지, 기존 rejection 경로 확인 | 게이트를 유지하고 문제 콘텐츠 수정 |
| 배포/RSS 실패 | 이미 게시한 batch를 다시 번역·중복 생성하지 않음 | 동일 SHA의 배포와 피드 캐시 상태를 먼저 복구 |

중단은 해당 번역/발행 workflow와 진행 중인 실호출 실행을 대상으로 한다. 기존 legacy `auto`로 돌아가면 다른 호출이 발생할 수 있으므로 **먼저 workflow를 중지**하고, T5 executor 주입과 새 Secret 전달을 제거한 복구 PR을 만든다. `--use-ai none`만으로 한국어 번역이 완성되지는 않는다. 수동 검수 발행은 한국어·중복·출처·통계 검사를 모두 통과해야 한다.

rejection 디렉터리는 workspace의 공개 산출물 경로와 분리하고 파일 0600·디렉터리 0700을 유지한다. 마스킹된 whitelist 자료도 제한된 담당자만 읽으며 raw 원문 백업으로 간주하지 않는다. 운영 artifact 업로드 전 별도 비밀 검사를 수행하고 접근·보존 기간(제안 7일)을 설정한다. Slack에는 실행 URL·오류 분류·단계만 전송하며 비밀과 본문을 붙이지 않는다.

이미 배포된 잘못된 글은 이력을 재작성하거나 일괄 삭제하지 않고 수정/되돌림 PR로 처리한다. 게시 파일·게시 URL tracker·manifest를 함께 대조해 아직 공개되지 않은 URL만 다시 큐에 넣는다. 성공한 URL을 tracker에서 지워 재발행하는 방식으로 복구하지 않는다. 재개 기록에는 담당자·원인·규칙/모델·원장 잔액·검수 PR·배포 SHA·RSS 검증을 남긴다.

## 영속 저장소와 장애 복구의 구체화

단일 Mac mini 실행 주체, canonical 장부 경로, 비공개 백업 위치, 잠금 협조·검증·복구 및 재개 체크리스트를 [영속 장부 운영 런북](../runbooks/translation-ledger-storage-backup-recovery.md)에 정리했다. 같은 SSD의 복사본은 호스트 손실에 대비한 원격 백업을 대체하지 않는다. 외부 백업 목적지와 실제 비용 정산 연결이 확정·검증되기 전까지 운영 실호출을 활성화하지 않는다.
