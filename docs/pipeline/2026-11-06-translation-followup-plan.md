# 자동 번역 연결 후속 계획

상태: 계획. 이번 회차는 사용자가 확정한 대로 한국어 검수 발행에 집중한다. 새 제공자 호출, 키 등록, 일정 변경은 아직 실행하지 않는다.

## 완료 조건

공식 원문을 보존한 한국어 제목·요약이 생성되고, 기존 날짜·구조·한국어·고유명사·중복·통계·이미지·전체 테스트 게이트를 통과한 결과만 게시한다. 번역 실패가 워크플로 성공으로 보이거나 영어 글이 그대로 발행되지 않아야 한다. 최종 성공은 커밋 SHA, 게시 URL, RSS 항목과 배포 결과로 확인한다.

## 1. 제공자 결정과 자격 증명

- 호스트의 Claude·Codex 사용 방침을 기준으로 Claude API 또는 OpenAI API 중 하나를 결정한다. 키가 없는 환경에서 작동한다고 가정하지 않는다.
- GitHub Actions 실행이면 선택한 제공자의 저장소 Secret과 가용성을 검증한다. 키는 출력·캐시·번역 파일·PR에 넣지 않는다.
- 로컬 도구를 사용하는 방안은 별도 실행 계정과 self-hosted runner 운영 비용·복구 책임을 검토한 뒤 비교한다. 개발자 로그인 세션을 무인 운영 자격 증명으로 간주하지 않는다.
- 다른 제공자는 별도 명시적 허용 후 사용한다. 이번 계획은 특정 유료 API 사용을 승인하거나 호출하지 않는다.

## 2. 번역 계약

입력은 기사 ID, canonical URL, 원문 제목·요약, 출처, 원문 발행 시각이다. RSS와 웹 원문은 신뢰하지 않는 데이터로 취급하며 포함된 명령을 실행하지 않는다. 입력 크기를 제한하고 원문 링크 접근은 기존 URL 검증 경로를 사용한다.

출력은 기사 ID에 연결된 한국어 제목·요약과 번역 상태다. CVE, 버전, 금액·비율, 날짜, 제품명은 원문과 대조한다. 번역 모델에 취약점 심각도나 조직 침해 여부를 새로 판정시키지 않는다. 원문 주장과 편집자의 적용 의견은 별도로 보존한다.

캐시 키는 canonical URL, 원문 해시, 번역 규칙 버전, 제공자·모델 식별자를 포함한다. URL만 같고 내용이 바뀐 경우에는 캐시를 재사용하지 않는다. 단위 작업 ID와 재시도 횟수를 기록하고 이미 검증된 결과를 반복 과금하지 않는다.

## 3. 실패 처리와 비용 통제

- 키 누락: 발행 전 명확한 구성 실패로 종료하고 결과를 초안으로 보존한다.
- 시간 초과·429·일시적 5xx: 제한된 지수 백오프 후 실패를 유지한다.
- 401·403: 반복 호출하지 않고 인증 오류로 분류한다.
- 출력 형식·숫자 보존·한국어 검증 실패: 검수 큐로 보내고 게시하지 않는다.
- 기사 수, 입력 길이, 실행 시간, 호출 횟수 및 일일 예산의 상한을 정한다. 모델별 실제 요금 확인 후 비용 기준을 확정한다.
- 검증을 우회하거나 다른 유료 제공자로 조용히 전환하지 않는다. 번역할 수 없는 경우 수동 검수 경로를 명시적으로 사용한다.

## 4. 구현 순서와 검증

1. 현재 번역 진입점과 USE_AI 모드의 동작을 조사한다. 제공자 선택과 키 유무를 독립 검사한다.
2. 제공자 어댑터를 기존 유틸리티에 연결하고 HTTP 오류·형식·캐시 테스트를 먼저 작성한다.
3. 고정된 기사 fixture로 제목·숫자·고유명사·링크·프롬프트 주입 입력을 검사한다. 단위 테스트는 외부 API를 호출하지 않는다.
4. 명시적으로 선택한 제공자로 기사 소수만 dry-run하고 결과와 원문을 검수한다. dry-run은 파일을 쓰지 않아 전체 발행 게이트 검증을 대체하지 못한다.
5. 임시 디렉터리에 글과 이미지를 실제 생성해 모든 corpus 게이트, Ruff 검사와 format 검사, Mypy, 전체 pytest, Jekyll 빌드를 수행한다.
6. 격리 브랜치 PR에서 Actions와 Vercel 배포를 확인한다. 초기에는 병합 전 검수를 유지한다.
7. 운영 발행 후 SHA·canonical URL·파일명 날짜 redirect·RSS를 대조한다. 공급자 실패 시험에서도 자동 게시가 멈추고 초안이 보존되는지 확인한다.

## 5. 관측과 롤백

기사별 접수·번역·검증·게시 상태, 처리 시간, 캐시 적중, 오류 분류, 사용량을 집계한다. 원문 본문 전체·비밀·토큰은 로그에 기록하지 않는다. 경보에는 실행 URL과 실패 단계만 포함한다.

문제가 생기면 자동 번역·발행 실행을 멈추고 마지막 정상 설정으로 복원한다. 이미 게시한 글을 일괄 삭제하거나 Git 이력을 재작성하지 않는다. 수정이 필요한 글은 별도 검수 커밋으로 고친다.

## 이번 회차에서 분리된 항목

PR #803의 검수 글 반영과 production/RSS 검증을 먼저 완료한다. 전역 보호 훅의 원격 전송 제한과 Vercel 로그 인증 문제는 번역 제공자 연결과 별개로 다룬다.

### 권장 PR 묶음

1. **계약과 회귀 테스트 PR:** T1·T3. 네트워크나 API 키 없이 실행한다.
2. **제공자·캐시 PR:** T2·T4. 제공자 선택 후 구현하며 단위 테스트는 계속 외부 호출을 차단한다.
3. **발행 연결 PR:** T5·T6. 번역 실패를 게시 성공으로 처리하지 않는 경계를 확인한다.
4. **운영 검증 기록:** T7. API 제공자·일일 상한·비밀 보관·실패 대응 책임을 확정한 뒤 수행한다.

### 중단 조건

T2의 제공자·비용 기준이 미결정이면 다른 제공자를 자동 선택하지 않는다. T6의 Secret 또는 T7의 배포 로그 접근이 없으면 해당 단계만 차단 상태로 남기고 오프라인 테스트까지 완료한다. 실패 시 검사를 끄는 변경은 어떤 작업 단위에도 포함하지 않는다.

## T1·T3 구현 상태

`translation_contract.py`에 오프라인 계약을 구현했다. 기존 enhancer의 호출 순서와 실제 제공자 연결은 변경하지 않았다. 현재 설정의 `auto` fallback과 신규 계약의 명시적 `claude`/`openai` 선택을 구분하며 T2 연결 시 변환을 명시해야 한다.

구현 범위는 키 유무·명시적 제공자 선택, timezone이 있는 원문 요청, 고정 출력 스키마, 기사 ID·canonical URL·한국어·숫자·CVE·명시적 보호 용어 보존이다. 편집 의견은 원문 사실 검증과 분리한다. 네트워크와 프로세스 호출을 금지한 회귀 테스트로 검증한다. 의미적 충실도, 전체 프롬프트 주입 방어, DNS·리다이렉트 안전성 또는 게시 승인을 보장하는 계약은 아니다.
