# scripts/digest_midword_baseline.txt
# Grandfathered mid-word table cells (deny-by-default single-syllable tail).
#
# EMPTY as of 2026-09-07. The gate is now a pure blocking gate with no
# exemptions. Keep it that way.
#
# Each line would be "<post filename>\t<last 24 chars of the offending cell>" —
# keyed on the text, NOT the line number, because line numbers shift on any edit
# and a baseline that silently stops matching turns a blocking gate green. The
# count is ratcheted by test_digest_midword_baseline_does_not_grow.
#
# History, because the reasoning matters more than the number:
#
#   44  A corpus sweep found 44 mid-word cells in 37 published cron digests,
#       produced by the RSS pre-truncation bug: the feed handed us a summary it
#       had already cut, and _korean_brief_summary erased the trailing ellipsis
#       that marked the cut.
#   42  2 of those were never that bug. They were category-rollup rows cut by
#       _extract_trend_keyword's Korean hard slice — a second, still-live
#       truncation site the RSS fix had not touched. Fixed and repaired.
#    0  The remaining 42 cells were rewound to a word boundary, removing only
#       the dangling partial token (min 2 / median 2 / max 16 characters). No
#       network, no invented text.
#
# The header used to claim "their source text is long gone, so completing the
# words would mean inventing them". That was wrong: all 42 sources were live and
# still contained the cut fragment verbatim. It stayed wrong for a while because
# the first probe reported 8 of them dead — the variable was the User-Agent, not
# the link. GeekNews answers an unrecognised UA with a browser check served as
# HTTP 200 and a 260-character body, so the status code said nothing. Recovering
# the full sentences was possible but rejected on measurement, not on principle:
# appending to the next terminator added a median of 268 and up to 8402
# characters, because Korean summary bullets end in ~음/~함 rather than a period,
# so the rule runs into the next bullet. notes/midword-resummarize.md has the
# option-by-option comparison.
#
# Do NOT add a line here to make a new digest pass. Neither generator path emits
# these any more, so a fresh hit means either a THIRD truncation source or a
# word that belongs in _SINGLE_SYLLABLE_ALLOW — check the actual cell first.
