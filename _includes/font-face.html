{%- comment -%} Self-hosted Noto Sans KR — 2-tier woff2 subset. Tier-1 (this @font-face): every Hangul syllable used anywhere in the corpus + Latin + Jamo + symbols (~205-215 KB / weight, eager preload). Its unicode-range stays broad on purpose — the tier-1 woff2 is always fetched, so enumerating its ~1k syllables here would only add ~7.5 KB of inline CSS per page. Tier-2 (on-demand): the Hangul tail (~470-500 KB / weight). Declared in assets/css/font-tier2.css with a unicode-range disjoint from tier-1's actual glyph set, attached after `load` by head-runtime.js#loadFontTier2. A browser therefore fetches tier-2 only when a page renders a syllable the corpus has never used. See scripts/build/generate_noto_2tier_subset.py for the source pipeline (it generates both the woff2 files and font-tier2.css from one codepoint set, which is what keeps the two ranges in sync). Font URLs go through `relative_url`, NOT a bare /assets/fonts/... path. The GitHub Pages backup builds with --baseurl "/tech-blog", so a root-relative URL there resolves to twodragon0.github.io/assets/fonts/... and 404s — which is exactly what the backup did until 2026-08-10 (verified live: the /tech-blog/ prefixed URL returned 200 / 206,788 B while the bare one returned 404). The consequence was silent: Korean text fell back to the system font and the two preloads were wasted 404 round-trips. Do NOT use `absolute_url` either — see the SEO anti-patterns table in CLAUDE.md; assets must resolve against whichever origin served the HTML. {%- endcomment -%}
